🐛 BUG 1 : CONFLIT CONTRAINTES SQL OPERATOR

┌──────────────────────────────────────────────────────────────────────────┐
│ Problème                                                                 │
├──────────────────────────────────────────────────────────────────────────┤
│ Deux contraintes CHECK coexistent sur operator :                        │
│ 1. Contrainte inline : operator IN ('airtel', 'moov')                   │
│ 2. Contrainte nommée : operator = 'moov'                                │
│                                                                          │
│ Résultat : Insertions operator='airtel' échouent avec erreur confuse    │
└──────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────┐
│ Solution Appliquée                                                       │
├──────────────────────────────────────────────────────────────────────────┤
│ ✅ Boucle FOR qui supprime TOUTES les contraintes CHECK sur operator    │
│ ✅ Ajout d'UNE SEULE contrainte nommée : payments_operator_check        │
│ ✅ Mise à jour de create_payments_table.sql pour cohérence              │
└──────────────────────────────────────────────────────────────────────────┘

🐛 BUG 2 : PERTE DE JOURS D'ABONNEMENT

┌──────────────────────────────────────────────────────────────────────────┐
│ Problème                                                                 │
├──────────────────────────────────────────────────────────────────────────┤
│ La fonction updateUserSubscription() calcule TOUJOURS :                 │
│                                                                          │
│   expiresAt = NOW() + durationDays                                      │
│                                                                          │
│ Sans vérifier s'il existe un abonnement actif.                          │
│                                                                          │
│ Exemple :                                                                │
│   - Abonnement expire le : 31 janvier                                   │
│   - Le 21 janvier, paiement de 30 jours                                 │
│   - ❌ Avant fix : Expire le 20 février (perd 10 jours !)               │
│   - ✅ Après fix : Expire le 1er mars (garde ses 10 jours)              │
└──────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────┐
│ Impact Financier                                                         │
├──────────────────────────────────────────────────────────────────────────┤
│ 100 utilisateurs × 10 jours perdus = 1000 jours                         │
│ 1000 jours ÷ 30 = 33 mois                                               │
│ 33 mois × 5000 FCFA = 165,000 FCFA de perte ! 💸                        │
└──────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────┐
│ Solution Appliquée                                                       │
├──────────────────────────────────────────────────────────────────────────┤
│ ✅ Récupérer d'abord la date d'expiration actuelle                      │
│ ✅ Si abonnement actif (date > NOW), ÉTENDRE à partir de cette date    │
│ ✅ Si abonnement expiré, PARTIR de NOW                                  │
│ ✅ Si premier abonnement, PARTIR de NOW                                 │
│ ✅ Logs ajoutés pour debugging                                          │
└──────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────┐
│ Fichiers Modifiés                                                        │
├──────────────────────────────────────────────────────────────────────────┤
│ • supabase/functions/validate-transaction/index.ts (lignes 198-262)     │
└──────────────────────────────────────────────────────────────────────────┘
