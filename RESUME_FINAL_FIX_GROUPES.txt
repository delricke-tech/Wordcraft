📋 DIAGNOSTIC
═════════════════════════════════════════════════════════════════════════
Symptômes :
  • Erreurs 500 (Internal Server Error) dans la console
  • Page /groups ne charge pas ou affiche une erreur
  • URLs concernées : /rest/v1/group_members et /rest/v1/groups

Cause Identifiée :
  • Politiques RLS (Row Level Security) trop restrictives sur Supabase
  • Références circulaires lors des jointures SQL avec !inner
  • Deadlock : groups vérifie group_members qui vérifie groups...

Impact :
  • Vous êtes le seul utilisateur MAIS ça bloque quand même
  • Supabase retourne 500 au lieu de 403 ou des données vides

═════════════════════════════════════════════════════════════════════════

✅ SOLUTION (2 minutes)
═════════════════════════════════════════════════════════════════════════

Étape 1 : Aller sur Supabase
  → https://supabase.com
  → Sélectionner votre projet
  → Cliquer sur "SQL Editor" (menu gauche, icône </>)

Étape 2 : Exécuter le Script
  → Cliquer sur "+ New query"
  → Copier-coller FIX_RLS_GROUPS_SIMPLE.sql
  → Cliquer sur "Run" (ou Ctrl+Enter)
  → Attendre 2-3 secondes
  → ✅ Messages verts = Succès !

Étape 3 : Tester
  → Retour sur votre app
  → Aller sur /groups
  → Appuyer sur F5 (actualiser)
  → ✅ Plus d'erreur 500 !

❓ FAQ
═════════════════════════════════════════════════════════════════════════

Q : Est-ce dangereux de rendre les groupes publics lisibles ?
R : Non ! C'est le comportement NORMAL. Les groupes publics doivent être
    visibles par tous. Sinon ce n'est pas "public".

Q : Mes données privées sont-elles exposées ?
R : Non ! Les groupes privés (is_public = false) restent protégés.
    Seuls les membres peuvent les voir.

Q : Pourquoi l'erreur 500 et pas 403 Forbidden ?
R : Les doubles EXISTS créaient un deadlock. Supabase ne savait pas
    comment résoudre la requête et abandonnait avec une erreur serveur.

Q : Faut-il modifier le code TypeScript ?
R : Non ! Le code TypeScript est correct. Seules les politiques SQL
    Supabase devaient être corrigées.

Q : Faut-il relancer l'application ?
R : Non ! Juste actualiser la page (F5) suffit. Les politiques sont
    côté serveur, pas côté client.

Q : Que faire si ça ne marche toujours pas ?
R : 1. Vider le cache (Ctrl+Shift+R)
    2. Se déconnecter/reconnecter
    3. Vérifier que le script s'est bien exécuté (messages verts)
    4. Exécuter VERIFICATION_RLS_GROUPES.sql pour diagnostiquer
